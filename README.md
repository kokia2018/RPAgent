# RPAgent · 浏览器创作工作台

纯前端的通用创作工作台：在 **Agent** 对话里绑定工作空间、开发文件，在 **试玩** 窗口里使用成果，再把当前展示版本作为单文件带走。角色卡只是输入素材之一；常用功能通过作品组件接入，不把工作台变成专用酒馆。

> **实现与边界分开看。** [plan.md](plan.md) 是产品规则和唯一验收标准。当前已实现对话/空间绑定、常驻窗口、固定执行目标、展示源码快照导出和版本化角色组件。PNG/V2/V3 文件由 Agent 工具写进工作区，不要求作品页自带导出按钮。选择性备份恢复、完整酒馆语义和组件市场不在本轮完成声明内。

## 启动

开发和测试推荐 Node.js 22.22.2 或更高的 22.x。执行后打开终端地址（默认 `http://localhost:5173`）。静态部署的工作台不要求用户安装 Node.js，也不要求工作台业务后端。

```bash
npm install
npm run dev
```

## 当前版本怎么用

1. **打开网页或文档。** 从输入框旁「附件」加入文件。HTML 批次只有一个入口时可直接打开，多个则选入口；相对脚本、样式、图片应一起上传。本地查看不需要模型。txt、md、json 等通过文档阅读器查看；PDF/Word 暂不支持正文提取，Agent 不得声称已读取正文。
2. **修改当前空间。** 从「更多 → 设置」填写兼容端点、模型和 Key，服务需支持浏览器跨域、流式 `chat/completions` 和工具调用。Agent 修改工作副本，并刷新本次执行固定的目标窗口。新构建失败保留旧页面；重导附件不会覆盖已改工作副本。新上传附件同时保留原始 Blob 和只读文本索引。
3. **装配角色应用。** JSON/PNG 卡识别后，可点「生成角色试玩页」，本地生成独立的 `source.json`、`manifest.json`、`index.html`。`character-base@1.0.0` 提供基础单聊、开场、预设、世界书位置、续玩、流式和取消，不是完整酒馆。Agent 改源后用 `component reassemble` 更新；手改生成页会拒绝自动覆盖。PNG 和指定 V2/V3 JSON 用 `component export` 写入 `/cards/`，在「对话工具 → 作品文件」下载。V3 仅检查支持的字段/容器类型，未作第三方兼容认证。
4. **下载正在看的版本。** 试玩「导出」绑定已展示构建的源码快照，不会在失败留屏时偷换成最新源。HTML 编译为独立单页；TXT/Markdown/JSON 在阅读器按显示版本原格式下载，不含阅读器外壳。文件面板也可打开阅读器。

手机切换 Agent / 试玩，电脑可分栏；默认青雾绿，可切雾紫樱粉，作品本身的样式不被宿主主题改写。多个对话可绑定同一空间，历史分开而文件共享；打开过的对话和空间保持挂载。Agent 同空间排队、跨空间独立；用户界面切换不改运行目标。支持 Web Locks 的浏览器同时提供跨标签页串行，无此能力时只保证本页队列。

## 新版下载与备份规则（目标，未全部实现）

| 目的 | 目标行为 |
|---|---|
| 带走当前试玩成果 | 展示 HTML 时下载同一展示构建的单 HTML；展示 txt/md/json 时下载同一文件版本的原格式，不把阅读器包装进去。 |
| 带走未附组件的内容 | 标准装配作品可另选“导出当前内容原格式”，通过已验证的编码/映射生成，不调用 Agent；这不是下载最初原件。 |
| 下载原件或其他产物 | 原件单独保留；Agent 制作的带封面卡、素材和其他文件从工作空间文件面板下载。不支持的格式编码不能用改后缀代替。 |
| 备份作品数据 | 只保证标准接口登记的聊天、记忆、进度；精细导出由组件提供，不自动抓取任意页面内存。默认下载应用不夹带玩家历史。 |
| 备份工作台 | 完整或选择业务数据范围，排除密钥和临时授权。恢复默认导入新空间、保留未选数据；明确报告缺失和不能恢复的项目。 |

**现有备份行为不要误用新版目标：** 当前项目包导入新建任务，但不含作品业务存档；当前完整备份恢复会**替换现有业务数据**，尚无选择性恢复。现有 `rpagent-saves` 可迁移标准存档，排除 `ai:*`，但其范围仍偏当前任务而非单个窗口。操作前看清当前界面的范围与警告。

不扩建复杂版本系统，也不把里程碑快照/回退演练作为新版发布门槛；现有覆盖、删除和恢复前的保护继续保留。文本快照不是完整文件或玩家存档备份，无法保护的破坏式操作会被拒绝。

## 工作台发行与作品交付

```bash
npm run typecheck     # 类型检查
npm test              # 自动化测试
npm run build         # 工作台静态部署构建：dist/
npm run preview       # 本地检查上述构建
npm run build:single  # 工作台自身的单文件：dist-single/index.html
```

工作台的发行 HTML 与用户下载的作品 HTML 是两件事；文档成果本身不必转 HTML。标准 AI 作品导出后应自带 API 配置和调用实现，不带工作台 Key，调用模型仍需联网。

当前推荐本地或 HTTPS 静态服务。单文件已能构建，但工作台双击 `file://` 的存储、请求与预览边界仍须按浏览器实际验收；兼容预览模式依赖 Service Worker，不能在 `file://` 使用。单文件打包成功不等于所有双击运行能力已通过。

## 本轮验证结果

类型检查、22 个测试文件 / 170 用例、普通构建及单文件构建通过。真实 `deepseek-v4.1-flash-1017` 长任务首轮因测试脚本未挂载对应预览空间触及 18 轮预算，挂载后在同一对话续跑 11 轮正常完成；实际验证添加、完成、筛选、删除、空输入拒绝、改标题后存档恢复及 offline-static HTML 导出。新端点在共 29 轮 / 37 工具的历史续接中没有 API 错误，不代表无限长任务或所有端点兼容。PNG/V3 双导出也已用真实模型验证，详情见设计记录。
