# RPAgent

**纯前端的、可以边玩边改的 AI 交互应用开发平台。**

> 用 Agent 把各种技能与组件装配成一个完整的页面 —— 写、跑、玩、改、带走，都发生在同一个浏览器标签页里。

大多数「AI 做应用」给你一个**结果**：一段代码、一个链接、一份一次性的产物。RPAgent 做的是另一件事 —— **让应用在你玩它的同时，继续被对话改写。**

左边是 Agent，右边是正在运行的应用。你说「把结算改成双栏，加一个失败重试」，它会真的去写文件、构建、刷新这个窗口，读回真实报错，再改一遍。不必复制代码，不必重新部署，不必离开这个页面。改完的那一刻，你眼前的还是那个能玩的页面，而不是一份需要另找地方打开的源码。

整个平台跑在浏览器里：没有服务端，没有账号体系，项目和资料留在你自己的浏览器里；模型端点由你指定，密钥由你保管。

**打开即用：** [kokia2018.github.io/RPAgent](https://kokia2018.github.io/RPAgent/) —— 无需安装，也不必登录。

## 我们相信什么

### 运行中的那个版本，才是唯一真相

预览不是截图，也不是聊天框里的一段代码。试玩窗口是一个活的程序，Agent 与它共享同一个工作空间：写入、构建、观察、再写入，构成一个闭合回路。

导出时带走的是**当前正在展示的那次构建**，而不是磁盘上某个更新的源码；一次构建失败会保留旧页面，因为正在被玩的东西不该被悄悄弄坏。所见、所玩、所得，必须是同一个东西。

### Agent 是组装者，不是聊天机器人

Agent 通过工具真正动手：读文件、写文件、构建、打开试玩、读取控制台与 DOM、模拟交互、导出成品。可复用的经验、配方与资料作为**技能**挂进对话；常用能力则做成**版本化的作品组件** —— 识别、装配、重组、导出都是本地确定性过程，合规输入不必惊动模型；只有不兼容的输入和个性化定制，才交给 Agent 去改派生副本。不同的技能与组件最终收敛成一个完整、可运行的页面。

这让工作台保持通用，让复杂度长在作品里：宿主只负责对话、文件与运行，玩法与界面属于作品本身。

### 浏览器就是完整的运行环境

界面之下，是 IndexedDB 里的虚拟工作空间、sandbox iframe 里运行的作品、Web Worker 里的独立计算、Service Worker 提供的虚拟文件源，以及跨标签页的执行队列。

作品在隔离环境里运行，默认拿不到工作台的同源权限；AI 调用由用户在试玩区显式授权，密钥只留在父页，桥上只回传文本。API Key 不进备份、不进导出、不进作品。自由度来自边界清晰，而不是权限全开。

### 交付，意味着可以离开平台

完成的作品编译成一个独立单 HTML，自带存档与 AI 设置，可以在别处打开，不依赖工作台，也不带走工作台的凭据。文档保持原格式，不把阅读器外壳塞进交付物。开发过程可以是多文件工程，交付可以是一个文件 —— 这两件事互不妥协。

平台提供服务，不占有作品。

### 不伪造，是对创作者最基本的尊重

不能执行的就说不能执行，不能读取的不会假装读过，无法验证的不会报成完成。Agent 不许把「在聊天里输出代码」当作交付，必须落到真实文件。原始附件与常用资料只读，改动先复制；未知字段完整保留；无法映射的格式如实说明，而不是静默降级。

这套克制不是能力不足，而是让人敢把真正重要的东西交给它。

## 不挑题材：从一张角色卡到任意 AI 互动页面

工作台不预设你要做什么。放进来的可以是一张角色卡（JSON / PNG / V2 / V3）、一段互动叙事、一个已有的 HTML 小应用，或任意带 AI 交互的前端页面 —— 它们都被当作**输入**，而不是被要求先改成某种格式。

识别与装配交给标准组件：合规输入在本地确定性生成内容源、组件清单与页面，不必每次惊动模型；格式不标准、能力有缺口，或只是想加个新玩法时，Agent 在派生副本上适配，原始文件始终保留。角色卡只是这套通用能力最早被验证的一种素材，不是产品的边界。

## 一个回路，而不是一条流水线

```
说出意图 → Agent 落地为文件 → 试玩窗口真实运行 → 观察回传 → 继续改 → 带走单文件
```

反馈来自真实运行的 console、异常、网络失败与页面交互，不是模型对结果的想象。于是「改一下」不再意味着重来一遍：对话、文件、运行中的窗口始终指向同一个目标，切换界面不会改变执行归属，多个空间可以并行，同一空间内的写入保持串行。

## 构成

| 层 | 承担什么 |
| --- | --- |
| 对话与工作空间 | 意图、上下文、虚拟文件树，以及彼此独立的身份 |
| 工具与技能 | 让 Agent 能真正动手：文件系统、构建、观察、交互、资料库、组件、导出 |
| 作品组件 | 可识别、可装配、可重组的功能层，随作品运行，而不是塞进宿主界面 |
| 试玩窗口 | 常驻的独立运行实例，把结果变成可玩、可观察的事实 |
| 独立交付 | 把当前展示版本变成一个不属于任何平台的 HTML |

## 开始

开发构建需要 Node.js 22.x（**仅开发时**；运行时不需要，也不要求工作台后端）：

```bash
npm install
npm run dev
```

打开终端给出的地址，拖进一个 HTML、一份文档，或者直接从一句话开始。模型端点在设置里填写，兼容 OpenAI 风格的流式 `chat/completions` 与工具调用。

```bash
npm run typecheck
npm test
npm run build          # 工作台静态站点构建
npm run build:single   # 工作台自身的单文件构建
```

工作台是纯静态产物，可以直接发布到任意静态托管，打开链接即可使用；单文件构建不依赖同目录下的其他资源，尤其适合这种分发方式。导出的作品同样是独立单 HTML，也能这样分享。

## 技术

TypeScript · React 19 · Vite 8 · Dexie / IndexedDB · sandbox iframe + postMessage · Web Worker · Service Worker · Vitest。全部在浏览器内，没有后端。
